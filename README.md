# KBO SCOUTING LAB

KBO 시즌 기록에서 관찰할 선수를 찾고, 그 추천이 어떤 평가 기준에 의존하는지 검토하는 스카우팅 도구입니다. 같은 선수도 장타를 중시할 때와 삼진 억제를 중시할 때 순위가 달라집니다. 구단 전력분석가, 스카우트, 선수 평가 담당자가 **누구를 먼저 볼지, 어떤 조건에서 추천이 흔들리는지, 현장에서 무엇을 확인할지** 한 보고서에 남길 수 있도록 만들었습니다.

**제출용 사례** · [김도영 검증 리포트](docs/reports/batting-final.pdf) · [브랜든 검증 리포트](docs/reports/pitching-final.pdf) · [타자 기본 리포트](docs/reports/batting-basic.pdf) · [투수 기본 리포트](docs/reports/pitching-basic.pdf)

위 사례 PDF는 이전 화면에서 출력했습니다. 두 검증 리포트의 기준 점수와 상위 3위 유지 횟수는 현재 계산과 일치합니다. 이전 리포트의 ‘안정 대안’은 현재 화면과 새 PDF에서 ‘모델 추천 대안’으로 표시됩니다.

## 사용 흐름

1. **일반 스카우팅**에서 타자 또는 투수를 선택하고 시즌, 타자 포지션, 최소 PA 또는 IP를 설정합니다.
2. 평가 유형을 고르거나 사용자 지정 가중치(각 0~10)를 입력합니다. 추천 후보에서 최대 3명을 선택합니다. 이름·초성 검색으로 최소 출전에 미달한 선수의 기록도 조회할 수 있습니다.
3. 레이더, 성장 추세, 유사 선수, 현장 확인 탭을 검토합니다. 이 단계에서 **기본 리포트 PDF**를 바로 출력할 수 있습니다.
4. 선택적으로 **추천 결과 검증하기**를 엽니다. 선수 선택 시 적용된 조건을 그대로 사용하며, 서로 다른 조건에서 담은 선수는 기준선별로 구분합니다. 같은 조건의 직접 선택·모델 1위·모델 추천 대안을 한 표에 모읍니다.
5. 상대 순위와 표본을 검토한 뒤 선수별로 추천 유지·조건부 추천·추가 관찰 필요 중 하나를 직접 고르고 의견을 적습니다. 미작성 상태로도 출력할 수 있습니다. **검증 포함 PDF**는 기본 보고서 뒤에 검증 결과와 **계산 방식 · 가중치 · 판정 기준**을 덧붙입니다. 화면에서 상세를 접어 둔 상태에서도 출력됩니다. 일반 화면으로 복귀하면 선택과 필터가 유지됩니다.

일반 관찰 메모는 브라우저 저장소에 보관됩니다. 검증실 판단 초안은 현재 페이지에서 같은 조건으로 재진입하면 복원되며, 장기 보관은 PDF 저장을 사용합니다.

추가 기록 활용 → 추천 순위 안정성 · 선수별 강점/약점 · 기록 신뢰성 검토

| 용도 | 사용하는 기록 | 결과 |
| --- | --- | --- |
| 핵심 평가 | 타자 AVG·BB%·K%·ISO·SB/PA, 투수 K%·BB%·HR/9·WHIP | 선택한 비중으로 기준 점수와 순위 산출 |

| 검증 | 가중치 변경, PA·IP, 경기 수, 최근 최대 3시즌 | 순위 범위·상위 3위 유지 횟수, 표본 규모와 변동 폭, 대안 후보 |

| 대상 | 심층 지표 | 시즌 기록으로 계산하는 방법 |
| --- | --- | --- |
| 타자 | 홈런 생산 · 장타 구성 | HR/PA = HR ÷ PA. XBH = 2B + 3B + HR. XBH/H = XBH ÷ H |
| 타자 | 선구안·삼진 균형 · 주루 효율 | BB/K = BB ÷ SO. 도루 성공률 = SB ÷ (SB + CS). 성공·시도 횟수 병기 |
| 투수 | 탈삼진·볼넷 차 | K-BB% = 100 × (SO − BB) ÷ TBF, 단위 %p |
| 투수 | 9이닝당 볼넷·피안타·피홈런·탈삼진 | 각각 BB·H·HR·SO에 27을 곱해 정수 아웃 수로 나눔. 앞 세 지표는 낮을수록, K/9는 높을수록 높은 백분위 |
| 공통 | 연령 · 출전 규모 · 기록 변화 | CSV의 시즌 연령과 G, 타자 PA·투수 IP 표시. 최근 시즌 표에는 타자 OBP·SLG·HR/PA, 투수 K-BB% 포함 |

도루 성공률은 시도 기회와 함께 해석합니다. 연령은 기록 맥락으로만 표시하며, 출생연도와 시즌 연령이 충돌하면 보류합니다. 유효 비교 선수가 5명 미만이면 백분위를 보류하고, 분모가 0이거나 필요한 기록이 없으면 해당 비율을 계산하지 않습니다. 출전 기준을 충족한 선수에 한해 가장 높은 심층 지표가 75백분위 이상이면 상대 강점, 가장 낮은 지표가 25백분위 이하이면 추가 확인으로 표시합니다.

HR/PA·XBH/H와 ISO, K/9와 K%처럼 같은 사건을 공유하는 지표를 추천 점수에 중복 반영하지 않습니다. HR/9도 기존 핵심 축에 정해진 비중으로만 반영합니다. 시즌 실책·타점·득점으로 수비력이나 독립적인 공격 기여를 단정하지 않으며, 승·세이브·홀드에 능력 점수를 부여하거나 등판 역할을 추정하지 않습니다.

## 데이터와 지표

동봉 CSV는 모두 **1982~2026년, 45개 시즌**의 선수·시즌 단위 자료입니다. CSV의 URL 열에는 KBO 선수 기록 페이지가 있습니다. 원 수집처·수집일과 2026년 기록의 시즌 마감 여부는 메타데이터에서 확인되지 않습니다.

| 자료 | 원본 행 | 주요 컬럼과 처리 |
| --- | ---: | --- |
| [타자 시즌 CSV](kbo_comparison/kbo_batting_stats_season_1982-2026.csv) | 10,209 | Id, Born, Season, Team, Position, G, PA, AB, H, TB, BB, HBP, SF, SO, SB. 투수 타격행, 미출전, 중복 키, 필수 집계값 오류 등을 제외한 분석 엔진 기록은 9,818행 |
| [투수 시즌 CSV](kbo_comparison/kbo_pitching_stats_season_1982-2026.csv) | 7,971 | Id, Born, Season, Team, ERA, ER, IP, TBF, SO, H, HR, BB. IP를 정수 아웃으로 변환하며 30⅓이닝은 91아웃. ERA는 CSV 시즌값 사용 |

- 타자 AVG = H/AB, ISO = (TB−H)/AB, BB% = BB/PA, K% = SO/PA, SB/PA = SB/PA입니다. OPS는 (H+BB+HBP)/(AB+BB+HBP+SF) + TB/AB로 계산합니다.
- 투수 K%와 BB%의 분모는 TBF입니다. HR/9 = 27×HR/아웃, WHIP = 3×(H+BB)/아웃입니다. CSV에서 이닝과 ERA가 유효한 7,922행은 ER로 독립 계산한 9×ER/IP와 소수 둘째 자리 반올림 오차 범위에서 일치했습니다.
- 시즌 간 연결은 Id, 시즌 내 조회는 Id와 Season의 조합을 사용합니다. CSV에서 복수 ID가 쓰인 선수명은 타자 103개, 투수 85개입니다. 두 CSV 각각에서 중복 선수·시즌 키와 동일 ID의 출생일 충돌은 0건이었습니다.
- 포지션 필터는 기존 포지션 자료와 CSV를 사용합니다. 결측, 분모 0, 분석 제외, 기록 없음은 실제 0과 구분합니다. 원자료를 브라우저용 JS로 패키징하므로 정적 사이트에서도 계산할 수 있습니다.

## 분석 방법

**1. 후보 추천.** 선택 시즌과 포지션·최소 출전 조건을 만족하는 선수들을 기준 집단으로 삼습니다. 타자 K%, 투수 BB%·HR/9·WHIP은 낮을수록 유리하게 방향을 맞춥니다. 각 지표에서 유효 표본이 5명 이상일 때 다음 백분위를 사용합니다. 자신도 조건을 충족하면 표본에 포함합니다.

$$p_j = 100 \times \frac{n_{\mathrm{worse}} + 0.5n_{\mathrm{tied}}}{n_{\mathrm{valid}}}, \qquad S = \frac{\sum_{j:w_j>0} w_j p_j}{\sum_{j:w_j>0} w_j}$$

활성 지표 하나라도 백분위를 계산할 수 없으면 점수와 순위를 보류합니다. 점수는 표시할 때만 반올림합니다. 동점은 공동 순위(1·1·3)이며, 같은 순위 안에서 출전 규모·이름·ID 순서로 표시합니다. 비교 오차 허용 범위는 1e−10입니다. 후보 순위의 비교 집단과 레이더의 비교 집단은 다를 수 있습니다. 레이더는 기존 기본 기준인 같은 시즌·겹치는 세부 포지션 200 PA 이상 타자 또는 같은 시즌 30 IP 이상 투수를 사용합니다.

**2. 가중치 민감도.** 활성 지표를 하나씩 골라 원래 비중에 0.8 또는 1.2를 곱합니다. ±20%는 평가자가 비중을 조금 다르게 정했을 때의 영향력을 보기 위한 분석 조건입니다. 지표 자체에 대한 의존성은 그 지표를 제외하는 별도 시나리오로 확인합니다. 다른 가중치는 유지한 뒤 전체 합이 1이 되도록 정규화하고, 같은 후보 집단을 기존 점수 함수로 다시 평가합니다. 제외된 지표에만 결측이 있던 선수가 새로 순위를 받을 수도 있습니다.

**3. 순위 안정성.** 기준선과 정규화 비중이 같거나 서로 중복되는 시나리오, 비중 합이 0이거나 아무도 순위를 받지 못한 시나리오는 제외합니다. 선수별 순위 범위는 유효 시나리오의 최고~최저 순위입니다. 상위 3위 비율은 해당 선수가 3위 이내인 횟수 ÷ 해당 선수가 순위를 받고 순위 산출 후보가 4명 이상인 시나리오 수입니다. 분모도 함께 표시합니다. 활성 지표가 하나뿐이면 독립적인 변경 시나리오가 없어 안정성 산출을 보류합니다. 이 비율이 설명하는 범위는 가중치 변화에 대한 추천 순위의 민감도입니다.

**4. 대안 후보.** 미선택 후보 중 시나리오 최저 순위가 가장 양호한 선수를 제시합니다. 동률이면 기준선 순위를 우선합니다. 선택 선수와 모델 1위 등 역할이 겹치면 한 행에 표시합니다. 별도의 종합 신뢰도 점수는 계산하지 않습니다.

**5. 기록 신뢰성.** 선택 당시 최소 출전 기준 미달과 기준의 100~110%인 근접 표본을 구분합니다. PA·IP의 집단 내 백분위와 최근 최대 3시즌의 원래 수치를 함께 표시합니다. 지표별로 출전 기준을 충족한 유효 시즌이 두 개 이상일 때만 최댓값−최솟값을 계산합니다. 서로 다른 시즌의 비율을 평균하지 않습니다. 동일 ID에서 출생 정보가 충돌하면 기록 연결을 보류합니다.

**6. 지표 간 불일치.** 유리한 방향의 백분위로 앞 지표가 75 이상이면서 뒤 지표가 25 이하인 조합을 찾습니다. 타자는 OPS·BB%, AVG·ISO, ISO·K%, 투수는 ERA·BB%, K%·HR/9, WHIP·IP를 확인합니다. 이 표시는 특정 강점이 다른 지표에서도 뒷받침되는지 현장에서 살펴볼 근거입니다.

## 로컬 실행과 검증

화면은 HTML·CSS·JavaScript로 구성되며 차트는 SVG, PDF 출력은 브라우저 인쇄를 사용합니다. 데이터 패키징과 정적 빌드에는 Python 3, 계산 및 화면 회귀 테스트에는 Node.js를 사용합니다. 아래 명령은 저장소 루트 기준입니다.

```sh
python3 kbo_comparison/server.py
```

브라우저에서 `http://localhost:8000`을 엽니다. [로컬 시작 파일](kbo_comparison/index.html)을 직접 열어도 동봉 데이터로 분석할 수 있습니다. Cloudflare Pages용 정적 파일은 `python3 build_pages.py`로 `site/`에 생성합니다.

## 분석의 한계

시즌 누적 기록에는 수비 동작, 구속·구종, 부상과 회복 상태, 계약 조건이 담겨 있지 않습니다. 적은 출전 기회는 수치 해석의 제약이며 선수의 향후 부진을 뜻하지 않습니다. 시즌별 리그 환경과 역할도 달라 기록 변화만으로 성장이나 쇠퇴를 확정할 수 없습니다. 가중치·시나리오·표본 기준에 따라 추천은 바뀝니다. 미래 성공 확률과 예측 정확도는 이 분석으로 산출할 수 없습니다. 최종 판단에는 경기 영상, 현장 관찰, 의료·계약 등 별도 확인 자료가 필요합니다.
